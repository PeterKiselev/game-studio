## 2. Схема подключения (если путь окажется доступен)

Три части, как сформулировал Codex:

1. **Клиент.** В адаптере для `vk_client=ok` — платёжный путь через `FAPI`
   (`showPayment`), а не `VKWebAppShowOrderBox`. Каталог — тот же `ITEMS`
   (`code` = sku), цена — в ОК-валюте (**курс/таблица цен неизвестны** — нужны
   от ОК). `caps.payments` включается только если `FAPI` реально доступен.
2. **Сервер.** Новый маршрут в `services/payments`: GET-callback по протоколу
   ОК. Ответ `true`/ошибка 1001/104 в нужном формате и с Content-Type
   `application/json`.
3. **Проверка.** Подпись `sig` (MD5 — то же вычисление, что уже есть для VK в
   `services/payments/src/index.ts`, но **другой ключ**: секрет приложения ОК),
   цена и код товара по каталогу, защита от повторных callback одного
   `transaction_id`. Покупка выдаётся только после этого.

Стоит заметить: Worker сейчас **stateless**, а «выдача покупки» происходит на
клиенте по успешному ответу платёжного окна. Для ОК тоже можно так же, но тогда
защита от повторов `transaction_id` и от «клиент соврал» остаётся такой же
слабой, как у VK. Это не блокирует, но решение стоит принять осознанно.

## 3. Что неизвестно и как проверить (без трат)

| Вопрос | Как проверить |
|--------|---------------|
| Доступен ли `FAPI`/`OKSDK` внутри нашего мини-приложения в ОК и какие параметры запуска приходят. | Диагностика Sudoku (`?diag=1`) печатает **имена** параметров запуска (`api_server`, `apiconnection`, … или только `vk_*`). Нужно открыть тестовую сборку внутри настоящего ОК — способ запуска в ОК документация не описывает (§ «Для Одноклассников» в `docs/vk-test-address-2026-10.md`). |
| Есть ли у созданного в ОК приложения настройки платежей (callback-URL, секрет). | Владелец смотрит раздел приложения в кабинете ОК после «Привязать OK ID» и присылает **названия** пунктов, не ключи. |
| Работает ли `showPayment` для приложения, созданного через VK Mini Apps. | Только ответ поддержки либо тестовый платёж в ОК (платёж — только по отдельному разрешению). |
| Условия: комиссия, курс «оки»→рубли, выплаты, нужен ли отдельный договор. | Ответ поддержки. Из прочитанных страниц не следует. |
| Нужна ли для платежей отдельная модерация/верификация платёжной части. | Ответ поддержки; правило 6 — валидация цены — известно. |

## 4. Решения-ворота

1. Диагностика показала `api_server`/`apiconnection` **и** у ОК-приложения есть
   поля callback/секрета → путь B реалистичен: запросить у Codex задачу на
   реализацию (клиент + Worker-маршрут + тесты с подписью и повторами).
2. Параметры только `vk_*` или нет настроек платежей → путь закрыт до ответа
   поддержки; платежи остаются выключенными.
3. Любой реальный платёж — только отдельное разрешение владельца.
