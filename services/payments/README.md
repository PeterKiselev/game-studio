# Сервер платежей «Дачных тайн»

Первый и единственный сервер во всей студии — остальные игры статические,
без бэкенда. Нужен только затем, что VK Mini Apps по-настоящему платит
голосами лишь через сервер, который подтверждает заказ (см. `src/index.ts`
для деталей протокола и почему сервер сделан статeless).

## Что это делает

Принимает POST-уведомления от VK (`get_item`, `order_status_change`),
проверяет подпись защищённым ключом приложения и отвечает в формате,
который просит VK. Ничего не хранит — покупка применяется на клиенте
в `games/dachnye-tainy/src/main.ts`, сервер только подтверждает VK, что
заказ настоящий.

## Деплой (Cloudflare Workers, бесплатный тариф)

```bash
cd services/payments
npm install
npx wrangler login          # откроет браузер, войти/создать аккаунт Cloudflare
npx wrangler secret put VK_APP_SECRET
# ↑ вставь сюда защищённый ключ приложения из dev.vk.ru — НЕ в файл,
#   именно в этот интерактивный запрос. Ключ ищи в настройках приложения
#   «Дачные тайны» (обычно в «Настройки» → «Информация» внизу страницы,
#   или в «Разработка» → «Ключи доступа» — если не найдёшь с первого
#   раза, пришли скрин, сверим вместе).
npm run deploy
```

Последняя команда напечатает адрес вида
`https://dachnye-tainy-payments.<твой-поддомен>.workers.dev` — это и есть
URL для вебхука.

## Подключение в VK

1. dev.vk.ru → «Дачные тайны» → «Платежи» → «Подключение».
2. «URL для платёжных уведомлений ВКонтакте» — вставь адрес выше.
3. «Тестировщики платежей» — добавь себя, чтобы проверить без списания
   настоящих голосов.
4. «Сохранить».

## Проверка

Открой игру внутри VK (`vk.com/app54767366`), зайди на участок — должна
появиться кнопка «🛍️ Магазин» (она видна всем на VK, `caps.payments`
у адаптера включён всегда; настоящее списание работает только после
этой настройки). Купи любой из двух товаров — в тестовом режиме голоса
не спишутся, но покупка должна применяться (кнопка меняется на
«Куплено», реклама/лимит подсказок — соответственно).

## Каталог товаров

Один источник правды на два места — держи их синхронными:

| | Клиент | Сервер |
|---|---|---|
| Список SKU | `games/dachnye-tainy/src/main.ts` → `SHOP_ITEMS` | `services/payments/src/index.ts` → `ITEMS` |

Цена в `ITEMS` — то, что реально спишется, клиент цену не знает и не
показывает (VK сам рисует её в своём окне покупки по ответу `get_item`).

## Одноклассники (подготовлено, не развёрнуто, не включено)

Схема — `docs/ok-dachnye-tainy-payments-2026-10.md`. В коде:

| Маршрут | Что делает |
|---|---|
| `POST /` | как раньше: ВК и `get_item` из ОК (`site=OK` → цена в ОКах, если `priceOk` задана, иначе ошибка) |
| `GET /ok` | подтверждение покупки ОК (`callbacks.payment`): подпись (`OK_APP_SECRET`), товар, сумма по `priceOk`, учёт в KV, ответ `true`; повтор той же `transaction_id` снова `true` без второй записи; сбой записи — ошибка, не `true` |
| `GET /ok/restore?vk_*=…&sign=…` | восстановление: проверяет подпись запуска (`VK_APP_SECRET`), только `vk_client=ok`, отдаёт `{ "skus": [...] }` |

Намеренно не заполнено (ничего не угадываем): `priceOk` у товаров, `OK_APP_SECRET`,
KV-привязка `PURCHASES` (см. `wrangler.toml`). Пока их нет, `/ok` отвечает
ошибкой и никому ничего не подтверждает. Клиентская часть (кнопка в игре, цены
в ОКах, вызов восстановления) **не подключена**: магазин в ОК выключен.
